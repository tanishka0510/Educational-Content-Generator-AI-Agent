# State Design

## Project

Educational Content Generator AI

Module: Orchestrator Agent

Version: 1.0

---

# 1. Introduction

The State Design defines the shared data model used throughout the Orchestrator Agent.

The state acts as the central communication medium between all participating agents during workflow execution. Instead of exchanging information directly, each agent reads from and writes to the shared state.

This approach ensures consistency, modularity, traceability, and easier workflow management.

---

# 2. Purpose

The shared state is designed to:

- Store all workflow-related information.
- Enable communication between agents.
- Maintain execution context.
- Preserve intermediate results.
- Track workflow progress.
- Support error handling.
- Maintain session continuity.
- Produce the final response.

The state serves as the single source of truth for every workflow.

---

# 3. Design Principles

The shared state follows the following principles.

## Single Source of Truth

All workflow data is stored in one centralized state.

---

## Agent Independence

Agents never communicate directly.

Every agent only reads from and writes to the shared state.

---

## Minimal Coupling

Agents are unaware of the internal implementation of other agents.

---

## Extensibility

New state sections can be added without affecting existing workflows.

---

## Traceability

Every stage of workflow execution can be tracked using the state.

---

# 5. State Structure

The shared state is organized into the following sections.

```
AgentState

├── Request
├── Session
├── File
├── Content
├── Educational
├── Multimedia
├── Workflow
├── Response
└── Error
```

Each section has a dedicated responsibility.

---

# 6. State Sections

## 6.1 Request

Stores information about the current user request.

Contains:

- User Query
- Detected Intent
- Workflow Category
- Timestamp
- Request ID

Purpose:

Represents the original request throughout workflow execution.

---

## 6.2 Session

Stores conversation-related information.

Contains:

- Session ID
- Conversation ID
- User ID (Optional)
- Previous Context
- Conversation History (Reference)

Purpose:

Supports follow-up questions and conversational continuity.

---

## 6.3 File

Stores uploaded document information.

Contains:

- File Name
- File Path
- File Type
- File Size
- Upload Status

Purpose:

Provides document information for content processing workflows.

---

## 6.4 Content

Stores outputs generated by the Content Processing Agent.

Contains:

- Extracted Text
- Clean Text
- Chunks
- Metadata
- Language
- Embeddings Reference
- Document ID

Purpose:

Provides processed educational content for downstream agents.

---

## 6.5 Educational

Stores outputs generated by the Educational Content Generator Agent.

Possible Outputs:

- Summary
- Quiz
- Flashcards
- Learning Objectives
- Explanation
- Comparison
- Assignment
- Programming Content
- Mathematics Solution
- Study Plan
- Recommended Resources

Purpose:

Stores all educational content generated during execution.

---

## 6.6 Multimedia

Stores multimedia outputs.

Contains:

- Audio
- Transcript
- Audio Duration
- Media URLs

Purpose:

Stores multimedia learning resources.

---

## 6.7 Workflow

Tracks workflow execution.

Contains:

- Current Agent
- Completed Agents
- Pending Agents
- Execution Status
- Start Time
- End Time

Purpose:

Allows the Orchestrator to monitor workflow progress.

---

## 6.8 Response

Stores the final response.

Contains:

- Success Status
- Response Data
- Message
- Generated Timestamp

Purpose:

Represents the final output returned to the frontend.

---

## 6.9 Error

Stores workflow errors.

Contains:

- Error Code
- Error Message
- Failed Agent
- Retry Count

Purpose:

Supports debugging and graceful error handling.

# 8. State Ownership

Each component is responsible for updating specific sections.

| Component | State Sections |
|------------|----------------|
| API Gateway | Request, Session, File |
| Orchestrator Agent | Request, Workflow, Response, Error |
| Content Processing Agent | Content |
| Educational Content Generator Agent | Educational |
| Multimedia Agent | Multimedia |

This ownership model prevents multiple components from modifying the same state unnecessarily.

---

# 9. State Update Rules

The following rules govern state updates.

- Only the owning component should modify its designated section.
- Agents may read any required section.
- Existing data should not be overwritten unless necessary.
- New outputs should be appended or merged where applicable.
- Errors must always be recorded in the Error section.
- The Response section is populated only after successful workflow completion.

# 11. Conclusion

The shared state serves as the central communication layer for the Orchestrator Agent.

By maintaining a structured and centralized state, the Orchestrator can coordinate multiple AI agents while ensuring consistency, modularity, scalability, and maintainability.

The design also enables future enhancements without requiring major architectural changes.
